Reorder Alert API Test

MVP uses localStorage for persistence - no backend server required

Note: This MVP implementation uses browser localStorage for data persistence. All API operations are simulated client-side. Future versions will include a REST API with the endpoints documented below.

Authentication

POST /api/auth/register localStorage

Register a new user account

POST /api/auth/login localStorage

Login with email and password

POST /api/auth/logout localStorage

Log out current user

Items

GET /api/items localStorage

Get all items for current user

POST /api/items localStorage

Create a new item

GET /api/items/:id localStorage

Get a specific item by ID

PUT /api/items/:id localStorage

Update an existing item

PUT /api/items/:id/quantity localStorage

Update item quantity (quick update)

DELETE /api/items/:id localStorage

Delete an item

Alerts

GET /api/alerts localStorage

Get all active alerts (items below threshold)

POST /api/alerts/:id/resolve localStorage

Mark an alert as resolved (ordered)

POST /api/alerts/:id/snooze localStorage

Snooze an alert for a specified duration

Settings

GET /api/settings localStorage

Get user notification settings

PUT /api/settings localStorage

Update user notification settings

Data Export

GET /api/export/csv localStorage

Export all items as CSV file
